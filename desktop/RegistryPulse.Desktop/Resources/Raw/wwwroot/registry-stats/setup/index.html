Registry Pulse is a local, file-based dashboard for multi-registry package metrics.
Setup: define portfolio, generate snapshot.
Dashboard: view summary, breakdown, leaderboard.
Data: stored locally on Desktop; static JSON on web.
Registries: npm, PyPI, NuGet, VS Code Marketplace, Docker Hub, GitHub Releases.
Privacy: no telemetry and no accounts. The portfolio stays in local files. Refresh reads public registry data and does not upload the portfolio. The assistant sends the injected snapshot through the local Ollama daemon, which can proxy a cloud model.

Portfolio Configuration

Select the registries and packages included in reporting. The portfolio file stays on this machine. Refresh reads public registry data and does not upload it.

Tracked Portfolio

Add packages by registry. One entry per line within each array. This file is the arrays npm, pypi, vscode, nuget, docker, and github, plus an optional npmMaintainer string. It is not registry-stats.config.json. A non-empty npmMaintainer is what the site fetch passes to stats.mine, which adds discovered names that are not already in the npm array. If discovery throws, the fetch warns and keeps the explicit npm list.

Registry Sync

Write-side companion — keep every registry in sync

registry-stats monitors downloads.registry-sync manages publishing. Together they close the loop: audit your org against npmjs and GHCR, detect version drift, find orphaned packages, and generate action plans — like Terraform for package registries.

Install
npm i -g @mcptoolshop/registry-sync
Audit
registry-sync audit --org my-org
Plan & Apply
registry-sync plan --org my-org
What it detects
✓ Current — published version matches repo
⚠ Behind — repo version ahead of published
✗ Missing — not yet published to registry
○ Orphan — published but no matching repo
